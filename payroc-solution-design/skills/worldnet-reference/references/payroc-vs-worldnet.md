# Payroc platform vs Worldnet platform - Solution Design mapping (derived)

> Compares what the **Payroc skills** (`../../<skill>/SKILL.md`, which mirror docs.payroc.com) say with what the **Worldnet snapshot** says.
> Only differences supported by those two sources are stated; everything else is marked **confirm with Product**.
> Snapshot paths are relative to `references/`; Payroc skill names are folders under `.claude/skills/`.
> Worldnet Boarding API is **not supported** (last row).

## Orientation (read first)

- **Different platforms/hosts.** Payroc REST: `api.uat.payroc.com/v1`, identity `identity.uat.payroc.com/authorize` (`x-api-key` -> Bearer, 3600 s), `processingTerminalId`, `Idempotency-Key` on POSTs
  (`integrate-hosted-fields`, `run-a-card-sale` skills). Worldnet REST: `testpayments.worldnettps.com/merchant/api/v1`, API key (Basic) -> JWT (`expiresIn` hours), `terminal`, `uniqueReference`, no documented idempotency header
  (`rest-api.md`, `auth-and-signatures.md`). **Keys, tokens, IDs and endpoints are not interchangeable** unless Product says otherwise.
- **HPP is the closest overlap.** The Payroc HPP skill (`integrate-hosted-payment-pages`) uses the same page paths (`/merchant/paymentpage`, `/preauthpage`, `/securecardpage`), the same field names
  (`TERMINALID`, `ORDERID`, `HASH`, `CARDREFERENCE`, `STOREDCREDENTIAL*`, `UNIQUEREF`...) and the same SHA-512 recipe, but on `payments.uat.payroc.com` / `payments.payroc.com` and with the Payroc Self-Care Portal.
  The Worldnet snapshot documents the same pages on `testpayments.worldnettps.com`. Whether a given merchant is hosted on the Worldnet or the Payroc host is a **provisioning question - confirm with Product**.
- **Mixed-brand page in the Worldnet wiki:** `pages/selfcare/api_specification/3d_secure_payroc.md` documents a Payroc-gateway 3DS flow (`payments.uat.payroc.com/merchant/mpi`, `singleUseToken`, `api.payroc.com/v1/payments`). Treat it as Payroc-platform content.
- **Same gateway, same device key injection.** Confirmed by Payroc: Worldnet and Payroc are one gateway with different APIs, so card-present key injection (TDES DUKPT) is the same for both, neither supports PCI DSS-validated P2PE, and device KSNs go to the project's Payroc SE (see `device-operations.md`).
- **Payroc owns the Worldnet gateway** (`integrate-google-pay/references/google-pay.md`: "Payroc now owns the Worldnet gateway and uses it to process transactions").

## Mapping table

|---|---|---|---|
| **Card sale (CNP API)** | `POST /v1/payments` (`run-a-card-sale`) | `POST /api/v1/transaction/payments`, `channel=WEB`/`MOTO`/`POS` (`rest-api.md`; spec op `payment`) | Different auth (identity service vs Basic->JWT), IDs (`paymentId` vs `uniqueReference`), terminal field names; Worldnet payload types KEYED/SECURE_CREDENTIALS/DIGITAL_WALLET/PAYMENT_TOKEN. Idempotency: Payroc required header; Worldnet **not documented**. |
| **Pre-auth / capture / reverse** | `POST /v1/payments` pre-auth, `/capture`, `/reverse`, `/adjust` (`run-a-pre-authorization`) | `autoCapture=false` (needs "Allow Pre-Auth"), `PATCH .../capture`, `PATCH .../reverse`; HPP `preauthpage` (`hosted-pages.md`) | Worldnet capture/reverse are PATCH on `{uniqueReference}`; no `/adjust` operation in spec (capture may differ in amount within processor margin). 3DS does not support pre-auths (Worldnet wiki). |
| **Refunds** | `POST /v1/payments/{id}/refund`, `/v1/refunds` (`refund-a-card-payment`) | `POST .../payments/{uniqueReference}/refunds`; unreferenced `POST /transaction/refunds` (`rest-api.md`) | Worldnet refund of an unsettled payment runs a **reversal**; unreferenced refunds are gated by support + acquirer. ## Using this table in a Solution Design
1. Identify which platform each merchant is **provisioned on** before choosing an endpoint family.
2. Never mix a Worldnet API key/terminal with Payroc endpoints (or vice versa) without written Product confirmation.
3. Carry every "confirm with Product" and "not documented in snapshot" item into the SD's open questions list.
